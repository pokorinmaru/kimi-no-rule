# 評価の取り決め 追補5（別のモデルによる後輩の言葉の判定・研究の種の数・判定用の問題）

この追補は、指示書 第10.2節と第10.3節にあって、これまで作っていなかった評価の部品を3つ足すためのものです。本物の Claude でこの部品を一度も回していない時点で、下の「凍結するファイル」を `evals/protocol-addendum-5.lock` で凍結します。凍結するまで、この追補の節（`leak-judge`、`research-judge`）を `--live` で回しません。凍結した後に数え方や判定用の問題を変える時は、新しい追補を足します。

追補4は第三者の評価データの取り込み用に予約されているため（`tools/evals/src/third-party.ts`）、この追補は5番にしました。

## 1. 後輩の言葉を別のモデルで判定する（節の名前 `leak-judge`）

### ねらい

core の関門は、決まった網（数、演算の名前、正誤を言う言葉）で後輩の発話を止めます。網の目をすり抜ける言い方（たとえば「お姉さんの方を1にするといいよ」のように、数も演算の名前も使わずに向きを教える言い方）は、関門の検査では見つかりません。そこで、同じ発話を別のモデルにも読ませ、関門とモデルの判定が食い違った件数を数えます。関門が設計どおりに動くか（既存の「後輩の言葉の漏れの比較」）と、網そのものの粗さ（この節）を、別の数として出します。

### やり方

- 行：既存の漏れの比較と同じ `evals/data/kohai/test.jsonl` の20行（第三者の行があれば、それも別の行として）。
- 後輩：漏れの比較と同じ2つ。答えと正しい世界を渡して「言わないで」と頼んだ Claude（sonnet-5.5）と、この作品の後輩（sonnet-5.5＋関門、落ちたら定型文）。定型文だけの後輩は、生成ではなく固定の文なので判定しません。
- 各行を5回ずつ言わせます（後輩ごとに100発話）。発話はこの節の中で生成し直すので、漏れの比較の表とは別の発話です。1つの発話について、core の関門（漏れの比較と同じ `leaksOf`）と判定のモデルの両方が判定します。
- 判定のモデル：haiku-5.5。既存の ClaudeClient の構造化出力で、`reveals`（明かしているか、真か偽）と `kind`（`answer` 答え・`value` 途中の値・`operation` 演算・`direction` 正しい向き、明かしていなければ `none`）を返させます。モデルには問題文・答え・もとにする量と比べる量の持ち主を渡し、発話は最後に渡します。指示文は `tools/evals/src/leak-judge.ts` の `LEAK_JUDGE_SYSTEM` です。
- 空の発話はモデルに送らず「明かしていない」とします。モデルが拒否した時や、返事が形に合わない時は「判定できなかった」とし、比べる数から外します。API のエラーは項目のエラーとして記録し、`--resume` でその項目だけ回し直します。

### 数えるもの（後輩ごと）

- 発話の数、関門が落とした数、判定のモデルが明かしているとした数
- 判定だけ：モデルが明かしているとしたのに関門が通した発話（網の粗さ）。割合とウィルソンの95%信頼区間を付けます
- 関門だけ：関門が落としたのにモデルは明かしていないとした発話（関門がモデルより厳しい所）
- 両方、判定できなかった数、モデルが挙げた種類ごとの数

数え方は `leak-judge.ts` の `sumJudged` です。割合の分母は、モデルが判定できた発話の数です。

### 扱い

モデルの判定は数えるためだけに使い、子どもに見せる発話を決めることはしません（正しさは core が決める）。発話の文そのものは保存しません（関門の種類と判定の結果だけを残す）。人による判定（100件）はこの追補に含めず、人の作業として残します。

## 2. 研究の評価で Opus の種の数を選べるようにする

- 実行の引数 `--seeds N` で、Opus が仮説を書く研究者を、模擬の子ども1人につき N 回（種 1〜N）会わせます。既定は1回で、これまでの結果と同じです。Claude を使わない基線は、これまでどおり5回です。
- 本番では `--seeds 3` で回します。
- 報告の表には、研究者ごとに「回数」（1人あたりの回数）の列を出します。研究者の名前にも回数が入ります（例：「研究層、1人3回」）。

## 3. 判定用の問題で「回復」を測り直す（節の名前 `research-judge`）

### ねらい

凍結済みの研究の評価（`tools/evals/src/research-eval.ts`）は、研究する側が問題を選ぶのと同じ銀行の問題で「回復」を判定します。銀行の問題で区別できない2つの読み方は同じとみなされるので、回復が甘めに出ます。研究する側に一度も出さない別の問題で判定し直し、2つの数を並べます。

### 判定用の問題

- `evals/data/research/judge-problems.ts` に8問。分数の倍の問題で、このリポジトリのために書いたものです。銀行と問題の id も文も重なりません。
- 変えてあるもの：先に出る持ち主、わかっている数、聞かれている数、1より小さい倍と大きい倍、単位分数、倍のまわりの言葉（の、倍、これ、をもとにすると、に対して）。
- `tools/evals/src/judge-problems.ts` が ProblemRecord に組み立て、そのテストが core の `validateWorld`・`validateStatements`・`solve`・`problemConditions` で全問を確かめます。よくある読み違いの一覧のどの2つも、8問のどこかで違う世界を作ることも確かめます。
- 作ったのは作者側で、第三者ではありません。人の確認（human_checked）はまだです。

### やり方

- 凍結済みの `runEpisode` をそのまま使います。研究者を包む部品（`tools/evals/src/research-judge.ts`）が、研究者が確定として返した読み方を覚えておきます。
- 1回の会い方（エピソード）から、2つの判定を出します。銀行：凍結済みの評価と同じ判定。判定用：確定した読み方が、8問すべてで模擬の子どもの読み方と同じ世界を作れば回復、確定したのに回復でなければ誤った確定。
- 研究者は既存の研究の評価と同じです（列挙＋情報利得、列挙＋決まった順、一覧だけ、Opus）。Opus の回数は `--seeds` に従います。
- 報告：研究者・回数・読み方の種類ごとに、回復（銀行）・回復（判定用）・誤った確定（銀行）・誤った確定（判定用）を並べます。記述言語で書けない読み方の行は、回復ではなく誤った確定だけを見ます。

## 凍結するファイル

- `evals/PROTOCOL-ADDENDUM-5.md`（この文書）
- `evals/data/research/judge-problems.ts`
- `tools/evals/src/judge-problems.ts`
- `tools/evals/src/leak-judge.ts`
- `tools/evals/src/research-judge.ts`

凍結のコマンド（リポジトリの直下で）：

```
node tools/evals/src/check-protocol.ts --write evals/protocol-addendum-5.lock evals/PROTOCOL-ADDENDUM-5.md evals/data/research/judge-problems.ts tools/evals/src/judge-problems.ts tools/evals/src/leak-judge.ts tools/evals/src/research-judge.ts
```

lock は1つのコミットで足します（`pnpm check:protocol` が確かめます）。

## 本番の回し方（凍結の後）

```
pnpm eval:live -- --only leak-judge --concurrency 8
pnpm eval:live -- --only research-judge --seeds 3 --concurrency 8
```

研究の評価そのもの（凍結済みの節）を3回で回し直す時は `pnpm eval:live -- --only research --seeds 3` です。どの節も、止まったら `--resume <runId>` で続きから回します。
